# Synthetic bound chain

The geometric painting and parts come from generateExampleParts. The labelled draft and production model come from generateExampleMeshDraft on those exact parts, with a producer-made torso mesh.

The setup still is the assembly recomposite, retained as synthetic setup evidence. The example demonstrates record binding. Rendered motion and camera behaviour require separate producer validation.

The public create CLI writes stage moves, signoffs, rig plan steps (plan add), parts step progress (step-status), rig/post review verdicts, the review package, immutable input inventory, the sealed scene and authored direction. The direction is direction@2, bound to that scene. The parts verdict is a synthetic review-tool export from tests/parts-package.ts, recorded as a producer step.

Two seed kinds cover plan.steps (setup and status progress) with split.parts, and the rig version declaration. Source inventory is registered by input add. Each seed declares its consuming command and records that command’s step index in chain.json.

checkpoints/ contains frozen prefix projects and adjacent pending-act declarations. Checkpoint 0a-interview-options follows interview-options rig_type and precedes the interview answers, the plan add calls and signoff interview; it has no skeleton.model.json and four expected INTERVIEW_INCOMPLETE refusal codes (interview.framing[rig_type].answer, interview.framing[reference].answer, interview.waypoints[seethrough].guide, interview.waypoints[assemble].guide) with zero warnings. Checkpoint 0b-plan-pending follows advance plan-approved with the plan add steps drafted and precedes signoff plan-approved; it has no skeleton.model.json, zero refusals and zero warnings. Stage 1 (1-parts-verdict, zero refusals, zero warnings) follows the producer parts-stage check report that the parts-review move binds, and precedes the synthetic review-tool parts verdict export and the structure-snapshot writer, which copies the meshes declarations of the labelled draft once that verdict is approved. Stage 2 (2-rigging-answers) precedes the first rigging answer and still needs later option sets to be agent-drafted in declared steps before registration by public writers. Pending answers use the SHA-256 of the file drafted during the walk. Stage 3 (3-rig-review, zero refusals, zero warnings) precedes rig review. Stage 4 (4-direction-post, zero refusals, zero warnings) precedes the background plate registration, the scene write, the declared agent-authored direction@2 input and the direction write. Pending stage moves use advance with the existing authorizing signoffs. Every file authored or copied for a later writer has a declared producer step with output hashes. The chain_step indices are zero-based. Stage 2 has four expected INTERVIEW_INCOMPLETE findings for its unanswered rigging guides (interview.waypoints[bones].guide, interview.waypoints[meshes].guide, interview.waypoints[constraints].guide, interview.waypoints[motion].guide) and zero warnings. Every prefix has zero warnings and records its stage moves in advances[]. tests/example-chain.test.ts checks these states.

Reproduce with `bun scripts/generate-example-chain.ts <fresh-dir> --check` from the create repository.
